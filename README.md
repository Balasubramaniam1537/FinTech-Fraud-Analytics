End-to-End FinTech Fraud Detection & Risk Analytics Pipeline

 1. System Architecture & Component Mapping
Storage & Compute:Google BigQuery (Sandbox environment serving as the primary analytical data store).
Data Science Workbench: VS Code / Anaconda Python 3 environment.
Modeling Framework: XGBoost Classifier paired with Scikit-learn preprocessing pipelines (`StandardScaler`, `train_test_split`).
Visualization Layer: Power BI Desktop connected via active GCP Service Account IAM endpoints.

---

 2. Data Engineering & SQL Feature Pipeline
The source ledger contains 50,000 transaction records with a highly sparse target label (1.41% absolute fraud rate). Rather than relying entirely on the machine learning model to discover patterns, three key risk features were engineered at the database layer using BigQuery SQL window functions:

user_historical_avg: Computes the customer's running average expenditure up to the current transaction timestamp. Used to flag consumption deviations.
    ```sql
    AVG(amount) OVER(
      PARTITION BY user_id 
      ORDER BY timestamp 
      ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    )
    ```
`cumulative_tx_count`: Tracks transaction velocity over time to flag account takeovers and automated script attacks.
    ```sql
    COUNT(*) OVER(
      PARTITION BY user_id 
      ORDER BY timestamp 
      ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    )
    ```
`is_midnight_transaction`: Evaluates temporal risk profile deviations by categorizing operations executed between 00:00 and 04:00 AM.
    ```sql
    CASE WHEN EXTRACT(HOUR FROM timestamp) BETWEEN 0 AND 4 THEN 1 ELSE 0 END
    ```

3. Modeling Methodology & Evaluation Matrix
To mitigate data leakage, the 80/20 train/test split was completed prior to any transformation stages. Given the heavy 1:70 class imbalance, standard accuracy metrics would skew results. Imbalance optimization was handled natively by configuring the XGBoost `scale_pos_weight` parameter to match the inverse class ratio.

Confusion Matrix & Operational Output (Test Dataset: 10,000 Rows)
Global Classification Accuracy: 95.00%
True Negatives (Legitimate Cleared): 9,392 rows
True Positives (Fraud Caught): 83 cases
False Negatives (Missed Attacks):58 cases
False Positives (Good Users Blocked):467 cases
Operational Trade-off: The pipeline yields a ~1:5.6 False Positive ratio. In a production environment, this balanced approach ensures critical fraud vectors are captured while keeping manual review queues manageable for risk operations teams.

 4. Analytics Interface & Production BI
The scoring outputs generated by the Python model were pushed back into a dedicated BigQuery target table (`scored_predictions`) and joined 1:1 on `transaction_id` with the raw payment logs inside Power BI.

Custom Analytics Measures (DAX)
To monitor active platform risk vectors without relying on static row calculations, a dynamic DAX calculation was implemented to track the systemic fraud rate:
```dax
Fraud Rate % = DIVIDE(SUM(raw_transactions[is_fraud]), COUNT(raw_transactions[transaction_id]), 0)
```

 Dashboard Operational Modules
Executive KPI Strip: Surfaces high-level financial metrics: Total Monitored Volume (\$8.65M), Total Fraud Incidents (704 cases), and Global Platform Fraud Rate (1.41%).
Category Risk Distribution:Utilizes horizontal clustered bar elements to map absolute fraud counts against specific business channels, highlighting vulnerabilities in *Financial Services* and *Electronics*.

 Deployment & Local Execution

1.  Clone Source & Set Up Directories:
    ```bash
    git clone https://github.com
    cd FinTech-Fraud-Analytics
    ```
2.  Environment Configuration:
    ```bash
    pip install pandas numpy google-cloud-bigquery xgboost scikit-learn
    ```
3.  Data Generation:Execute `simulate_transactions.py` to create the mock database baseline.
4.  Cloud Provisioning:Create a `fraud_detection` dataset in BigQuery Sandbox, upload the generated CSV file as `raw_transactions`, and save your credentials file locally as `bigquery_key.json`.
5.  **Model Execution & Writeback:** Run `train_model.py` to trigger the analytical window query, train the XGBoost algorithm, and pipe the output arrays back to the cloud.
